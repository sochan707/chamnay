# Business Case — Sprint Backlog

Part of [Milestone 1](milestone_1.md). Write your parts in the [business case draft](business_case_draft.md).

**Team:** 4 people · **Names and due date:** To be added

## Member 1 — Problem and risks

- [ ] **User problem:** Say who needs the app and what problem it could help with.
- [ ] **Current options:** List how people handle the problem now.
- [ ] **Main risks:** List the main risks and one way to reduce each risk.

## Member 2 — Solution

- [ ] **App idea:** Explain the app in one sentence.
- [ ] **Included features:** List what the first version will do and how it helps.
- [ ] **Excluded features:** List what the first version of the app will not do.

## Member 3 — Budget

Budget means how much the project will cost. Do this before ROI.

- [ ] **Budget period:** Agree on how many weeks or months the budget covers.
- [ ] **Team time:** Add up team hours. Show the value of unpaid time apart from cash costs.
- [ ] **Cost list:** List each cost, such as tools and hosting. Include repeat costs for the full period.
- [ ] **Total cost:** Check prices, add some money for extra costs, and total it all.

**Output:** A cost table. Mark rough numbers as estimates. The current $2,288 is only an example.

## Member 3 — ROI

ROI shows the money gained compared with the cost.

- [ ] **Income plan:** Say who gets the return and how the project could earn money.
- [ ] **Expected income:** Estimate income for the same period as the budget.
- [ ] **Calculate ROI:** Use the formula below if the numbers are known and cost is above zero.
- [ ] **Check lower returns:** Check what happens if income is lower or costs are higher.
- [ ] **Other benefits:** List other expected benefits, such as easier spending plans, apart from money ROI.

**ROI = (income − cost) ÷ cost × 100%**

**Output:** A short note on whether the return is worth the cost. If income is unknown, say “ROI is not known yet.”

## Member 4 — Timeline and final edit

- [ ] **Team deadlines:** Set draft and final dates with the group.
- [ ] **Project steps:** Add key project steps and dates. Mark dates not yet agreed.
- [ ] **Final review:** Put all six parts together and check that the words and numbers match.

**Done:** All four members have read and agreed on the full business case.

**Remember:** No survey is planned. Mark ideas we have not proved as assumptions.
